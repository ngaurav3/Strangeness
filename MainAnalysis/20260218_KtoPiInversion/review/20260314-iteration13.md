### 2. Medium: the efficiency maps are derived over a broader reco-good acceptance than the later nominal PID fiducial, which is acceptable in principle but should be documented more explicitly

Relevant files:

- `/tmp/fhead_strangeness/MainAnalysis/20260305_PIDEfficiency/Efficiency_Variable_Binning.ipynb:181-186`
- `/tmp/fhead_strangeness/MainAnalysis/20260208_ReducedTreeProduction/DelphiFileConversion_v2.5.ipynb:549-564`
- `KtoPiAnalysis.cpp:1375-1379`
- `overleaf_repo_git/MCEfficiency/MCEfficiency.tex:54-67`
- `overleaf_repo_git/MCEfficiency/MCEfficiency.tex:116-116`

What is happening:

- In the March 5 variable-binning notebook, the reco-good selection used to
  derive the efficiency maps is:
  - `RecoCharge != 0`
  - `RecoGoodTrack > 0`
  - `p_T >= 0.4`
  - `|cos(theta)| < 0.95`
- The reduced-tree notebook then looks up a branch value for each reco track in
  `(P, cos(theta))`.
- The active analyzer later applies the tighter nominal PID fiducial through
  `passPIDFiducialFromMom`, corresponding to `0.15 < |cos(theta)| < 0.675`,
  before averaging those branch values over the selected tracks.
- The note already partly reflects this by showing the full map domain and the
  nominal fiducial boundaries in `MCEfficiency.tex`.

Why this matters:

- This is not automatically inconsistent. A broad per-track efficiency map can
  be derived first and then sampled inside a narrower final analysis fiducial.
- But the main note should say this explicitly, so readers do not infer that
  the efficiency maps themselves were derived only inside the nominal PID
  fiducial.

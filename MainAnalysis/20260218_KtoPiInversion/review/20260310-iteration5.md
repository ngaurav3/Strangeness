# Reviewer Report

Author: Yen-Jie Lee and OpenAI

## Scope

This review asks for the bottom-line unfolding test that should be used to pick
the unfolding parameter, rather than a broad menu of possible checks.

The question is simple:

- what is the minimum test package needed to justify the chosen unfolding
  setting?

## Bottom-line reviewer comment to the analyzer

The nominal unfolding parameter should be chosen from the first setting that
passes these three tests:

1. refolding test
2. mismatched-shape closure test
3. stability test against the neighboring parameter choice

That is the bottom line.

## Concrete test sequence

### 1. Refolding test

For each tested unfolding setting:

- unfold the nominal spectrum
- refold it back to reco space with the same response matrix
- compare refolded/reco in data
- compare refolded/reco in MC

Pass condition:

- the refolded/reco ratio is statistically consistent with unity in the
  populated bins
- no clear shape trend remains after refolding

Why this is the first test:

- if the unfolded result cannot reproduce the measured reco input after
  refolding, that parameter choice should not be used

### 2. Mismatched-shape closure test

For each tested unfolding setting:

- inject a nontrivially reweighted truth shape
- fold it to reco
- unfold it with the nominal response and nominal prior
- compare unfolded/injected

Pass condition:

- the unfolded/injected ratio is acceptably close to unity
- no large tail bias appears

Why this is the second test:

- nominal closure is too easy
- the parameter choice must also work when the truth shape is not the same as
  the one used to build the response

### 3. Neighboring-setting stability test

For each candidate nominal setting:

- compare the result to the next nearby setting
- for Bayes: compare `nIter` to `nIter + 1`
- for SVD: compare `kReg` to the nearest acceptable neighboring `kReg`

Pass condition:

- the change between neighboring settings is smaller than the statistical
  uncertainty in most populated bins
- the choice has entered a stability plateau

Why this is the third test:

- the nominal parameter should not sit in a rapidly changing part of the scan

## Concrete rule for choosing the parameter

### Bayes unfolding

Requested steps:

1. Scan `nIter = 1, 2, 3, 4, 5, 6`.
2. Apply the three tests above at each `nIter`.
3. Choose the smallest `nIter` that passes all three tests.

Bottom-line rule:

- choose the first stable iteration, not the largest one

### SVD unfolding

Requested steps:

1. Scan `kReg` over the active bin range.
2. Apply the same three tests.
3. Choose an interior `kReg` value in the stable region.

Bottom-line rule:

- do not choose an edge value of the scan unless the scan clearly shows that the
  stable region begins there

## Minimum outputs requested from the analyzer

The analyzer should provide, for both `N_tag` and `dNch/deta`:

1. one refolding plot
2. one mismatched-shape closure plot
3. one stability plot versus unfolding parameter
4. one short table stating which parameter was chosen and why it passed

## Practical reviewer acceptance rule

If the analyzer wants a one-line decision rule, I would state it as:

- choose the smallest unfolding setting that reproduces reco after refolding,
  closes on a mismatched-shape test, and is stable against the next parameter
  step

## Overall review status

This is the minimum unfolding-validation package I would consider sufficient for
parameter determination.

Everything beyond this is useful, but these three tests are the bottom-line
checks.

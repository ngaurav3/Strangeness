# Reviewer Report

Author: Yen-Jie Lee and OpenAI

## Scope

This iteration reviews whether the current analysis note and code use one
common particle-definition policy across the DELPHI truth path and the
standalone generator overlays for:

- `dN_ch/deta`
- `dN_ch/dy`
- `K/pi`

The review target is definition consistency, not unfolding quality or note
style.

## Findings

### 1. High: the charged-particle definition is still not one common definition across all generators

Relevant files:

- `KtoPiAnalysis.cpp:134-152`
- `BuildDNdEtaResponse.cpp:15-23`
- `tools/pythia8_generate_truth_kpi_dndeta.cc:28-35`
- `tools/hepmc3_to_truth_root.cc:29-36`
- `tools/herwig_ascii_to_truth_root.py:21-25`
- `tools/xscape_final_state_to_truth_root.py:19-23`
- `tools/pythia6_generate_truth_kpi_dndeta.f90:109-127`
- `tools/build_truth_kpi_vs_dndy_from_tree.cc:161-173`

What is happening:

- The active DELPHI truth path in `KtoPiAnalysis.cpp` and
  `BuildDNdEtaResponse.cpp` uses `IsChargedPDG`, which counts not only
  `e, mu, tau, pi, K, p` but also heavier charged hadrons such as `Sigma`,
  `Xi`, `Omega`, `D`, `Ds`, `B`, `Bc`, and `W`.
- The standalone PYTHIA8 / HepMC3 / Herwig-ascii converters instead use a much
  narrower `chargeFromPdg` or `charge_from_pdg` predicate that counts only
  `e, mu, tau, pi, K, p` as charged.
- The X-SCAPE converter uses `TDatabasePDG` charge directly, so it can count a
  broader set of charged hadrons than those converters.
- The PYTHIA6 direct truth generator counts all charged particles through the
  generator charge bookkeeping (`iq3 /= 0`), which is again a different
  predicate.
- The `dN_ch/dy` builder does not impose a new charged-particle definition; it
  just inherits the `charge` branch written by the upstream truth converter.

Why this matters:

- The answer to “what is a counted charged particle?” still depends on which
  generator pipeline produced the truth tree.
- That means the `dN_ch/deta` and `dN_ch/dy` activity axes are not yet one
  identical observable across the DELPHI truth branch and all model overlays.

### 2. High: the standalone `K/pi` curves still do not implement the same identified-hadron fiducial definition as the DELPHI truth branch

Relevant files:

- `KtoPiAnalysis.cpp:1352-1358`
- `KtoPiAnalysis.cpp:1395-1405`
- `BuildDNdEtaResponse.cpp:185-194`
- `tools/pythia8_generate_truth_kpi_dndeta.cc:277-286`
- `tools/hepmc3_to_truth_root.cc:251-260`
- `tools/herwig_ascii_to_truth_root.py:167-176`
- `tools/xscape_final_state_to_truth_root.py:183-189`
- `tools/build_truth_kpi_vs_dndy_from_tree.cc:168-173`

What is happening:

- In the DELPHI truth path, generator-level kaon and pion yields are counted
  only after all of the following:
  - species selection (`pi`, `K`, `p`)
  - `0.4 < p_T < 5.0 GeV/c`
  - the nominal PID fiducial via `passPIDFiducialFromMom`
- The standalone truth builders for the generator overlays apply the
  `0.4 < p_T < 5.0 GeV/c` window and the weak-daughter veto, but they do not
  apply the same DELPHI PID fiducial before filling the kaon and pion counts.
- The thrust-axis `dN_ch/dy` ratio builder inherits the same looser kaon/pion
  count from the stored truth tree.

Why this matters:

- The current standalone `K/pi` model curves are not strict like-for-like
  DELPHI-fiducial comparisons.
- They are still usable as generator-context curves, but they should not be
  described as using the same identified-hadron definition as the DELPHI truth
  branch unless that fiducial is actually applied.

### 3. Medium: the analysis note still overstates the amount of definition matching

Relevant files:

- `overleaf_repo_git/main.tex:847-850`
- `overleaf_repo_git/main.tex:923-931`
- `overleaf_repo_git/main.tex:1046-1049`

What is happening:

- The `dN_ch/deta` subsection says the observable is built from “all stable
  charged particles in MC,” but the actual charged-particle predicate is not the
  same in all code paths.
- The standalone-generator section says the samples are post-processed with “the
  same observable definitions used for the DELPHI comparisons,” which is too
  strong for the present implementation.
- The `dN_ch/dy` section says the identified-kaon and pion yields keep “the same
  fiducial analysis definition as the nominal branch,” which is not true for the
  standalone truth builders as currently written.

## Requested Fix

- Define one shared truth policy and use it everywhere:
  - `is_counted_charged_for_activity`
  - `is_counted_kaon_for_ratio`
  - `is_counted_pion_for_ratio`
- Decide explicitly whether the charged-particle activity count should follow
  the broader DELPHI `IsChargedPDG` list or a restricted light-charged list, and
  then implement that same choice in every standalone converter.
- If the standalone curves are intentionally left looser than the DELPHI truth
  fiducial, then the note should say so plainly and stop calling them “the same
  observable definitions.”

## Bottom Line

No, the current repo still does not use one identical charged-particle /
identified-hadron definition across the DELPHI truth path and all standalone
generators for `dN_ch/deta`, `dN_ch/dy`, and `K/pi`.
